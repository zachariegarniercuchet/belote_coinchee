# Brooklyn v3 hybrid — benchmark, 20 October 2026

V3 restores taking frequency to about 52%, but makes only 68–70% of contracts
at mean bids around 112–113. It wins 42/100 games against each opponent:
above v2's saved results, below v1's. The hybrid is not an improvement over
v1 on these development seeds.

## Frozen policy and protocol

- New run source: `7b3c7d26441b4c09cf0cce7947420b5f27506f1a`. V3 uses v1's
  individual hand evaluation plus v2's public partnership accounting. Partner
  support: +10 per trump J/9 and side ace, +20 for belote, counted once.
  No trump-ace support. Own opening bonuses are not counted a second time.
  Shared Brooklyn card play unchanged.
- V3 uses v2's suit-choice/entry machinery, not every v1 overcall restriction.
  Thus this experiment changes more than one isolated support parameter;
  differences cannot be attributed solely to the +20 belote rule.
- 200 new full games: 100 against each de Belote version, target 1000.
  Seeds 30000–30049, each played with Brooklyn on team 0 and team 1.
  Dealer `seed % 4`, bot RNG `seed * 17 + seat`. Current web engine,
  normal bot settings, display sleeps/broadcasts disabled. Runtime
  4.9 minutes. No tuning during or after the run.
- V1/v2 reference results are reused from
  [the risk-aware winner benchmark](2026-10-20-risk-aware-winners.md),
  frozen at `7fc077f9d733cde168dbc84bbfbd9a9c88713018`, with identical
  seeds/settings/card play. Their policy and game-engine source files were
  confirmed unchanged. These are comparisons against common opponents,
  NOT direct v3-versus-v1/v2 games.
- All 200 unique game keys and both swaps for each seed validated. Wins,
  played deals, declarations and made contracts reconcile to full records.
  No dropped games, outlier removals or outcome exclusions.
- Approximate 95% percentile-bootstrap intervals use 4,000 resamples of
  whole seed pairs, preserving dependent swaps and matching to the saved
  baseline. No normality assumption or hypothesis-test p-values.
  Pointwise exploratory intervals, not multiplicity-adjusted ranking tests.
- Reused development seeds, not independent holdout validation. Different
  bidding changes game lengths and later hands/contracts; matched seeds do
  not make these identical fixed-contract replays.
- No server restart, live-room changes or push.

| v3 − v1 | de Belote v3 | -6 | -16 to 4 |
| v3 − v2 | de Belote v3 | +16 | 5 to 27 |

The pointwise intervals support a v3 advantage over v2 on this sample, while
v3 trails v1 against de Belote v2. Its −6-point difference versus v1 against
de Belote v3 remains uncertain. These exploratory results are not universal
rankings or proof of performance on fresh seeds.

V3 declares roughly as often as v1, but its mean contract is about 10 points
higher and its conditional success is 8–11 percentage points lower. This is
consistent with excessive raising relative to the desired high-success
bidding style, not a demonstrated card-play difference: all versions share
the same playing policy. Contract selection also differs, so conditional
success alone is not a controlled same-hand comparison.

## Calibration — both views

Margin = trick points + dix de der + belote − numeric bid; no awarded
contract/coinche bonus. Failures remain in both views. The engine's majority
condition means a nonnegative margin is not always a successful contract.
All contracts in this new sample were numeric, not explicit Capot bids.

V3's ordinary cushion is only +7 to +9 points, compared with about +16 to +18
for v1/v2. Capots inflate the all-deal mean via their special dix-de-der score.
They are excluded ONLY in the clearly labelled ordinary-margin view, never
from outcome rates. Detailed bid/opening groups, margin buckets, opponent
metrics and actual trump-leading choices remain in the JSON.

## Reproduce and inspect

[Saved summary and paired outcomes](results-2026-10-20-hybrid.json) contains
four new bot-side rows, four reference Brooklyn rows, all 200 new game
outcomes, and four paired comparisons. Reference game outcomes are preserved
in the linked reference JSON. Full per-game deal records are produced by:

```powershell
.\.venv\Scripts\python.exe -B benchmarks/bots.py --brooklyn brooklyn_v3 --pairs 50 --workers 4 --output results.json
```

See [benchmark instructions](README.md). The default command still runs the
unchanged v1/v2 comparison; `--brooklyn` selects versions explicitly.
